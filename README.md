# OZON Analizer

Анализ начислений и каталога товаров OZON: дневные и товарные отчёты, сверка с
кабинетом продавца, импорт данных по расписанию.

---

## Что это

Сервис, который сам забирает у OZON финансовые начисления и каталог товаров, раскладывает
их по дням и по товарам и отвечает на вопрос «сколько я заработал и на чём».

Ключевое свойство отчётов — **они сходятся**. Сумма доходов по дням равна сумме по
товарам, а та равна сумме в кабинете OZON. Это не приблизительное совпадение: тождества
проверяются тестами на каждом прогоне.

Документация по API: [docs/API.md](docs/API.md).
Устройство кода: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Живая проверка на настоящих данных: [docs/VERIFY.md](docs/VERIFY.md).

## Быстрый старт

Нужен Docker. Java и Gradle ставить не нужно.

```bash
cp .env.example .env      # значения по умолчанию подходят для локальной БД
docker compose up --build
```

| Что | Где | Логин |
|---|---|---|
| Приложение | http://localhost:8080 | — |
| Проверка живости | http://localhost:8080/actuator/health | — |
| Контракт API | http://localhost:8080/v3/api-docs | — |
| Просмотр базы | http://localhost:5050 | `analizer@example.com` / `analizer` |

Первый запрос: зарегистрируйтесь, войдите, подключите маркетплейс.

```
POST /api/auth/register                        {"login":"…","password":"…"}
PUT  /api/marketplaces/ozon/credentials       {"clientId":"…","apiKey":"…"}
POST /api/marketplaces/ozon/imports/finance   {"dateFrom":"2026-09-01","dateTo":"2026-09-30"}
GET  /api/marketplaces/ozon/analytics/daily?dateFrom=2026-09-01&dateTo=2026-09-30
```

Подробности и все методы — в [docs/API.md](docs/API.md).

> Сборка образа занимает несколько минут: внутри подтягиваются зависимости Gradle.
> Повторные сборки быстрее — кэш Gradle хранится в томе `analizer-gradle-cache`.

### Без Docker

Нужны JDK 21 и Postgres.

```bash
cp .env.example .env
docker compose up -d postgres        # только база
.\gradlew.bat bootRun                # или ./gradlew bootRun на Linux/macOS
```

## Доступ

Сессия в куке, а не токен. Сессию можно оборвать — «выйти на всех устройствах» в схеме с
токеном превращается в самописный чёрный список, который потом забывают чистить.

```
GET  /api/auth/csrf      → кука XSRF-TOKEN
POST /api/auth/register  → 201
POST /api/auth/login     → 200, кука JSESSIONID
```

Дальше каждый запрос сам приносит куку. Для методов, меняющих состояние, значение
XSRF-TOKEN обязательно повторяется в заголовке `X-XSRF-TOKEN`.

**Реквизиты OZON не хранятся в `.env`.** Их вводит пользователь через
`PUT /api/marketplaces/{mp}/credentials`, и перед сохранением они проверяются настоящим
запросом к OZON: иначе о неверном ключе пользователь узнал бы через три неудачных импорта.

### Если фронтенд запущен отдельно

По умолчанию приложение отвечает только своему источнику. Фронтенд на другом порту
нуждается в явном разрешении:

```bash
APP_ALLOWED_ORIGINS=http://localhost:5173 docker compose up
```

Для публикации по HTTPS задайте `COOKIE_SAME_SITE=None` и `COOKIE_SECURE=true`. Без этого
браузер не примет куку сессии, и каждый запрос будет давать `401` при успешном входе.

## Настройки

Все настройки задаются переменными окружения; в `.env.example` — с комментариями.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5433/analizer` | База |
| `DB_USERNAME`, `DB_PASSWORD` | `analizer` | Доступ к базе |
| `SERVER_PORT` | `8080` | Порт приложения |
| `APP_ALLOWED_ORIGINS` | пусто | Источники, которым разрешён CORS |
| `COOKIE_SAME_SITE` | `Lax` | Политика кук; для HTTPS нужно `None` |
| `COOKIE_SECURE` | `false` | Флаг `Secure` на куках |
| `OZON_READ_TIMEOUT` | `60s` | Таймаут запросов к OZON |
| `SYNC_MATURITY_DAYS` | `3` | Окно зрелости: день окончателен, только если он старше |

Пустой `APP_ALLOWED_ORIGINS` — не заглушка, а решение по умолчанию: пока приложение
отдаётся со своего источника, CORS не нужен, а кука сессии не покидает свой домен.

## Разработка

```bash
.\gradlew.bat test              # полный прогон, ~7 минут
.\gradlew.bat test -Pfast       # только модульные тесты, без БД, секунды
.\gradlew.bat bootRun           # запуск с текущим .env
```

`-Pfast` исключает интеграционные тесты `*IT`. Почти всё время полного прогона уходит
не на сами тесты, а на подъём Spring-контекстов и Testcontainers, поэтому во время правки
кода запускать полный прогон незачем.

### Контракт API

`docs/openapi.json` лежит в репозитории и проверяется тестом на совпадение с тем, что
отдаёт приложение. После изменения любого метода пересоберите его:

```bash
.\gradlew.bat test --tests "ru.analizer.contract.OpenApiContractIT" -Panalizer.updateOpenApi=true
```

Иначе сборка упадёт — и это лучше, чем обнаружить расхождение при сборке фронтенда.

Типы для фронтенда генерируются из контракта:

```bash
npx openapi-typescript docs/openapi.json -o frontend/src/api/schema.d.ts
```

## Проверка на настоящих данных

Тесты проверяют логику на фикстурах. Сходение с реальной выгрузкой OZON проверяется
отдельно, скриптом:

```powershell
.\scripts\check-api.ps1 -Base http://localhost:8080
```

Скрипт проходит полный цикл и сверяет итоги: сумма по дням, сумма по товарам, разбивка
расходов, отсутствие двойного счёта возвратов. Подробности — в
[docs/VERIFY.md](docs/VERIFY.md).

Коллекция Postman для ручного прогона: `postman/ozon-analizer-catalog.postman_collection.json`.

## Что стоит знать

**Не все нули означают одно и то же.** Отчёт за период, который не загружался, возвращает
`200` со статусом `NOT_LOADED`, а не нули. Отсутствие данных — это состояние, а не сбой.

**Расходы по товарам меньше дневных.** Часть расходов не относится к конкретному товару.
Разница приходит отдельным полем `unallocatedExpenses` и не растворяется по товарам молча.

**Фильтр по автору находит разные написания одного человека.** Название приходит от OZON
как есть; полное имя, фамилия и варианты написания сопоставляются между собой.

**Ключ OZON хранится в открытом виде.** Утечка дампа базы даст доступ ко всем магазинам.
Запланировано шифрование AES-GCM с мастер-ключом — помечено как `TODO(#encrypt-credentials)`
в коде.

**Один аккаунт на маркетплейс на пользователя.** Два продавца на одном OZON эта схема не
поддерживает: молча выбрать один аккаунт значило бы отдать данные не того продавца.
