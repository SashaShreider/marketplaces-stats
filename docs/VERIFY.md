# Как проверить, что API работает

Два независимых способа. Первый — одной командой, второй — руками в Postman.

---

## Способ 1: одной командой

```powershell
.\scripts\check-api.ps1
```

Скрипт проверяет то, что увидит клиент, и печатает отчёт. Ничего не чинит и не
чистит.

| Что проверяется | Зачем |
|---|---|
| `/actuator/health` отвечает | приложение вообще запущено |
| гостю закрытый метод отвечает 401 | защита действительно работает |
| регистрация и вход проходят | пароль принят, кука сессии выдана |
| `GET /api/auth/me` отвечает тем же пользователем | сессия не подменилась |
| реквизиты маркетплейса принимаются | ключи прошли настоящую проверку в OZON |
| `apiKey` нет ни в одном ответе | секрет не утекает наружу |
| покрытие периода | сколько дней загружено и сколько с ошибками |
| **доходы − расходы = к выплате** | финансовая арифметика не теряет и не задваивает деньги |
| доходы по товарам совпали с дневными | два отчёта считают одно и то же |
| **расходы по товарам + без SKU = расходы по дням** | ни одна часть расходов не пропала |

Последние две проверки — главные. Пустой или правдоподобный на вид отчёт легко
принимаешь за честный, а расхождение в копейках означает потерянные или задвоенные
деньги продавца.

Код возврата `0` — всё сошлось, `1` — есть расхождения. В Windows код можно
посмотреть так:

```powershell
.\scripts\check-api.ps1; echo "код: $LASTEXITCODE"
```

### Что нужно скрипту

Запущенное приложение и `.env` с реквизитами:

```properties
# .env
OZON_CLIENT_ID=1154
OZON_API_KEY=ваш-ключ
```

### Загрузить период и сразу проверить

По умолчанию скрипт проверяет то, что уже загружено. Чтобы сначала загрузить:

```powershell
.\scripts\check-api.ps1 -RunImports -DateFrom 2026-08-01 -DateTo 2026-08-31
```

`-RunImports` делает два фоновых запуска — каталог и финансы — и ждёт их
окончания. Занимает столько, сколько займёт OZON; квоту тратит.

### Другие параметры

```powershell
.\scripts\check-api.ps1 -Base http://localhost:8080   # другой адрес
.\scripts\check-api.ps1 -Login ivan -Password '...'    # другой пользователь
.\scripts\check-api.ps1 -SkipCredentials               # не подключать маркетплейс заново
```

`409` на регистрации — не ошибка: логин уже существует, скрипт можно перезапускать.

## Способ 2: руками в Postman

Коллекция: `postman/ozon-analizer-catalog.postman_collection.json`
(импортируется в Postman через Import).

### Перед запуском

Впишите в **Variables** коллекции:

| Переменная | Значение |
|---|---|
| `baseUrl` | `http://localhost:8080` |
| `login` | свой логин |
| `password` | свой пароль, **минимум 8 символов** |
| `mp` | `ozon` |
| `day` | любой день, по которому есть данные |
| `periodStart`, `periodEnd` | период для отчётов |
| `ozonClientId`, `ozonApiKey` | реквизиты из личного кабинета OZON |

### Порядок запуска

Запускайте коллекцию **по порядку сверху вниз**, или запускайте папками целиком.

1. **00 — Вход.** Обязательный первый шаг. Проверяет, что гостю отвечают 401, затем
   регистрирует, пускает и подключает маркетплейс.
   Куки и заголовок CSRF Postman подставляет сам — руками ничего вписывать не нужно.
2. **03 — Импорт каталога.** Без него отчёт по товарам будет пустым.
3. **05 — Импорт начислений.** Тянет финансы за период.
4. **06, 07, 08** — отчёты.
5. **09 — Честность отчёта.** Сверки, которые должны сходиться.
6. **11 — Ошибки.** Проверка кодов 400/404/409.

### Что смотреть вручную

Вкладка **Tests** у каждого запроса: зелёная галочка — проверка прошла. Итог
прогона виден внизу, у каждой папки свой счётчик.

Если папка «падает целиком с 401» — не начат шаг 1. Сессии ещё нет.

## Если что-то не сходится

**`тождество доходы − расходы = к выплате` не сошлось.**
Часть начислений потеряна или задвоена. Смотрите `status` и `coverage` в ответе:
`NOT_LOADED` и `PARTIAL` означают, что период загружен не полностью, и доверять
цифрам нельзя — это честный отказ, а не ошибка.

**расходы по товарам не равны расходам по дням.**
Так и должно быть: расходы `NON_ITEM` и `CONTAINER` не относятся к товару и лежат
в поле `unallocatedExpenses`. Прибавьте его — и сойдётся. Если после этого не
сошлось на копейки, округление.

**`connected: false` в списке маркетплейсов.**
Реквизиты не заданы. Откройте папку «00 — Вход» и выполните «Подключить реквизиты
OZON». Либо посмотрите `data/authors`, `data/catalog` — нет.

**`400` на подключении реквизитов.**
OZON их отверг. Обычно перепутан `clientId` и `apiKey`, либо ключ истёк.

**`409` при запуске импорта.**
Либо маркетплейс не подключён, либо уже идёт пересекающийся импорт — тогда смотрите
поле `conflict` и `activeImportId`.

**`500` вместо `400` или `409`.**
Это ошибка приложения, а не ваш запрос. Смотрите лог.

## Чего скрипт не проверяет

- Не сравнивает цифры с личным кабинетом OZON: сверка с ЛК — ручная работа,
  и именно её нельзя автоматизировать.
- Не проверяет, что верны сами цифры OZON. Он проверяет, что приложение не теряет и
  не задваивает то, что OZON отдал.
- Не проверяет работу при нескольких экземплярах приложения: защита от параллельных
  импортов работает в пределах одного процесса.
